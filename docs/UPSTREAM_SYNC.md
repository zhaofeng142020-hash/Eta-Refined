# 上游同步说明

Eta-Refined 是 [Mangi-11/Eta](https://github.com/Mangi-11/Eta) 的派生仓库。为了让重构版持续获得原版的功能更新，同时避免重构成果被覆盖，本项目建立了一套受控的上游同步流程。

## 1. 同步源

- **唯一同步源**：<https://github.com/Mangi-11/Eta>（上游 `main` 分支）。
- **绝不涉及 dsh-Go**：[ccch1mneyyy/dsh-Go](https://github.com/ccch1mneyyy/dsh-Go) 仅作为 UI/UX 设计语言参考（AGPL-3.0），**不在任何同步脚本、工作流或分支中出现，也不合并其任何代码**。
- 同步以“上游功能更新”为目标，不引入与重构无关的第三方来源。

## 2. 目标分支与合入方式

- 同步结果**只能合入 `main`**，不直接推送其他长期分支。
- 所有同步**必须经 Pull Request 合入**，由维护者 Review 后合并，不做直接 push 覆盖。
- 同步 PR 的标题与描述需注明来源上游提交范围（commit 区间）与同步时间。

## 3. 同步频率

- **每日自动**：通过定时任务（cron）每日检查上游是否有新提交，有则创建同步分支并发起 PR。
- **手动触发**：维护者可在 Actions 中手动运行同步工作流，用于临时追赶或验证。

## 4. 冲突处理

当上游改动与重构保留区发生冲突时：

1. **不静默覆盖**：禁止用上游内容整段覆盖本仓库实现。
2. **自动创建 Issue**：同步任务自动开具 Issue，说明冲突范围。
3. **开启冲突 PR**：同时创建冲突 PR，并逐项**标注冲突文件与原因**（例如“`ui/components/` 上游调整了卡片圆角，与 Mist Glass 令牌冲突”）。
4. **人工裁决**：由维护者决定保留重构版、吸收上游版，还是二者合并；裁决结果写回 PR 说明。
5. **记录结论**：冲突处理完成后在 Issue 中记录最终选择，便于后续追溯。

## 5. 质量门禁

- **构建 / 测试失败不合并**：同步 PR 必须通过 Lint、单元测试与构建检查；任一失败即保持 PR 打开，不合并到 `main`。
- 失败原因需在 PR 中说明并修复后再尝试合并。
- 不因“追进度”跳过门禁。

## 6. 重构保留区清单

以下路径属于 Eta-Refined 的重构成果，上游同步时**优先保留本仓库版本**：

| 保留区路径 | 说明 |
| --- | --- |
| `app/src/main/kotlin/io/github/mangi/eta/ui/theme2/` | Mist Glass 设计令牌层 |
| `app/src/main/kotlin/io/github/mangi/eta/ui/onboarding/` | 首启配置向导 |
| `README.md` | 重构版说明文档 |
| `docs/` | 重构说明、同步说明、FAQ、归因等文档 |

> `docs/` 下若包含上游原有文档（如 `TECHNICAL.md`、`AGENT_RUNTIME.md`），同步时按文件级判断：新增的重构文档优先保留，上游对既有技术文档的更新可正常吸收。

## 7. 执行清单（供维护者参考）

- [ ] 确认同步源为 Mangi-11/Eta，无 dsh-Go 引用
- [ ] 从上游拉取到独立同步分支
- [ ] 生成 PR 指向 `main`
- [ ] 检查是否触及重构保留区
- [ ] 若有冲突：建 Issue + 冲突 PR，标注文件与原因
- [ ] 构建与测试通过
- [ ] Review 后合并
